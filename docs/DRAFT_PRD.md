## 1. วิสัยทัศน์ของผลิตภัณฑ์ (Product Vision)

สร้างพื้นที่ทำงานดิจิทัลแบบครบวงจร (All-in-One Workspace) สำหรับทีมวิศวกรคลาวด์ที่ใช้งานง่าย รวดเร็วแบบ Single-Page Application (SPA) โดยผสาน **"การบริหารโครงการและงานประจำวัน"** เข้ากับ **"การกำกับดูแลด้านความปลอดภัย (ISO 27001 / BOT)"** และ **"ผู้ช่วยอัจฉริยะ AI Copilot"** อย่างไร้รอยต่อ โดยไม่ต้องสลับไปมาระหว่างหลายโปรแกรม

## 3. แนวคิดโครงสร้างเมนูและการนำทางเบื้องต้น (Proposed Navigation & Views)

ในการออกแบบรอบแรก ทีมผลิตภัณฑ์เสนอให้แบ่งหน้าจอหลักในแถบเมนูด้านซ้าย (Sidebar) ออกเป็นมุมมองต่อไปนี้:
- **Overview:** หน้าสรุปภาพรวมจำนวนโครงการที่กำลังทำ งานด่วน และภาระงานของสมาชิก
- **Projects & Project Workspace:** รายการโครงการทั้งหมด เมื่อคลิกเข้าไปจะเห็นตาราง Gantt และเอกสารประจำโครงการ
- **Tasks:** กระดานงานรูปแบบ Kanban (`To do`, `In progress`, `Done`)
- **Knowledge:** คลังบทความและคู่มือปฏิบัติงาน
- **Compliance and Governance:** ตารางตรวจสอบความพร้อมด้านมาตรฐาน ISO 27001 / ธปท.
- **Team:** ทำเนียบสมาชิกและแถบแสดงภาระงาน (Workload)
- **Cloud resources & Reports:** ข้อมูลทรัพยากรคลาวด์และสรุปค่าใช้จ่ายรายเดือน
- **Admin & Logs:** หน้าจัดการระบบและดูประวัติความปลอดภัย

## 4. ร่างรายการฟีเจอร์เบื้องต้น (Initial Feature Backlog)

| หมวดหมู่ฟีเจอร์ | แนวคิดฟังก์ชันการทำงานเบื้องต้น (Initial Concept) | สถานะการออกแบบ |
|---|---|---|
| **Gantt Timeline** | แสดงงานตามช่วงวันที่ (Start – Finish) แบ่งตามเฟส (Phase) และลากปรับวันที่บนปฏิทินได้ | รอสรุปกฎการคำนวณวัน |
| **Task Details** | คลิกที่งานเพื่อดูรายละเอียด คำอธิบาย ผู้รับผิดชอบ และความสำคัญ (`Low`, `Medium`, `High`) | รอสรุปการเชื่อมโยง SOP/CR |
| **Knowledge Hub** | เขียนบทความด้วย Markdown และแนบไฟล์ประกอบได้ | รอสำรวจการรันโค้ด HTML โต้ตอบ |
| **AI Copilot** | กล่องแชตถาม-ตอบเกี่ยวกับข้อมูลในโครงการ | รอขยายขีดความสามารถด้านการสร้างงานอัตโนมัติ |

## 5. ประเด็นคำถามทางการออกแบบผลิตภัณฑ์ที่ต้องตัดสินใจ (Product Design Trade-offs & Open Questions)

> [!NOTE]
> ประเด็นเหล่านี้คือทางเลือกในการออกแบบผลิตภัณฑ์ (Design Decisions) ที่ถูกหยิบยกขึ้นมาวิเคราะห์ในขั้นตอน `/grill-with-docs` ก่อนสรุปเป็น PRD ฉบับสมบูรณ์:

### PDQ-01: จะคำนวณค่าภาระงาน (Workload %) ของสมาชิกอย่างไร?
- **ทางเลือก A:** ให้หัวหน้าทีมพิมพ์ตัวเลขเปอร์เซ็นต์เองในตารางผู้ใช้
- **ทางเลือก B (ที่เสนอเลือก):** คำนวณแบบไดนามิก (Dynamic Derivation) จากจำนวนงานที่ยังไม่เสร็จ (`status !== 'Done'`) ที่ผู้ใช้คนนั้นถือครองอยู่ (เช่น งานละ 20% สูงสุดไม่เกิน 100%) เพื่อไม่ให้ตัวเลขค้างหรือล้าสมัยเมื่อมีการปิดงาน

### PDQ-02: จะเชื่อมโยงงาน (Task) เข้ากับกระบวนการตรวจ Audit ของ ธปท. และ ISO 27001 อย่างไรให้ไม่เป็นภาระวิศวกร?
- **แนวทางที่เสนอ:** ในหน้าต่างแก้ไขงาน (`TaskDrawer`) ให้มีช่องเลือกผูก **Task SOP** (บทความจาก Knowledge Hub) และช่องเลือกผูก **Change Authorization** (เอกสารหมวด `CR` หรือ `CC` ของโครงการนั้น) โดยใช้สำหรับพิสูจน์ความพร้อมของงานในเฟส `Launch` หรือ `Deployment`

### PDQ-03: คลังความรู้ (Knowledge Hub) ควรรองรับเฉพาะ Markdown หรือรองรับเครื่องมือแบบ Interactive ด้วย?
- **แนวทางที่เสนอ:** ทีมวิศวกรมักต้องการสร้างเครื่องมือคำนวณ CIDR, ตารางเปรียบเทียบสถาปัตยกรรม หรือ Dashboard ย่อย จึงควรรองรับโหมด **Interactive HTML** เพิ่มเติมจาก Markdown โดยต้องรันภายใน `iframe` ที่เปิดระบบ Sandbox เพื่อความปลอดภัย และมีสารบัญ (TOC) นำทางอัตโนมัติสำหรับเอกสารยาวๆ

### PDQ-04: AI Copilot ควรเป็นแค่แชตถาม-ตอบ หรือควรช่วยลงมือทำงานได้ด้วย (Agentic Actions)?
- **แนวทางที่เสนอ:** ควรพัฒนาให้เป็น **Agentic Copilot** ที่ทำได้ 4 รูปแบบ:
  1. อ่านไฟล์แนบได้หลายรูปแบบ (รูปภาพ, PDF, Word, Excel, PowerPoint, อีเมล Outlook `.msg`/`.eml`)
  2. สกัดรายการงานออกมาเป็นชุด (**Batch Task Proposals**) ให้ผู้ใช้ตรวจทานและกดปุ่มสร้างเข้าโครงการได้ทันที (Human-in-the-Loop)
  3. ช่วยร่างและแปลงบทความในหน้าต่างเขียน Knowledge แบบวางคู่กัน (Side-by-Side Co-Author)
  4. เก็บประวัติการสนทนาแยกเป็นหลายหัวข้อ (Persistent Conversation Threads) ลงฐานข้อมูล

### PDQ-05: หน้าจอผู้ตรวจสอบ (`auditor`) ควรแสดงผลอย่างไรเพื่อให้เข้าใจชัดเจนว่าอยู่ในโหมดอ่านอย่างเดียว?
- **แนวทางที่เสนอ:** แสดงแถบแจ้งเตือนสีเหลืองอำพัน (Compliance Inspector Mode Banner) ด้านบนของทุกหน้าจอ ซ่อนปุ่มสร้าง/แก้ไข/ลบทั้งหมดใน UI และบล็อกคำสั่งแก้ไขที่ระดับ API ควบคู่กัน
